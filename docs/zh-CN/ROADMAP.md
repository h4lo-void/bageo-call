# 路线图

Bageo 1.0 对照大家对开源电话助理的期待做到了哪里，以及接下来值得做什么。这里没有任何承诺；欢迎提交 pull request。

## 这个项目有什么不同

大多数开源电话总机都需要 SIP 中继或云通信账号。Bageo 接的是**你本来就有的 SIM 卡**，用你桌上的一部手机，配合语音对语音模型：没有号码要租，延迟和插话由模型处理，而不是靠语音转文字、LLM、文字转语音串起来的一条链。从 1.0 开始，同一部手机也能用你自己的号码替你打电话。

## 对照社区需求的现状

✅ 已经有 · 🟡 部分有 · ❌ 还没有

### 接听来电

| 需求 | 现状 |
|---|---|
| 全天候接听、自由对话而不是按键菜单 | ✅ |
| 低延迟 | ✅ 语音对语音；手机还在响时就准备好开场白（实测从接起算中位数约 0.43 秒）。 |
| 真正的插话（barge-in） | ✅ 在收音不含 AI 自己声音的手机上（我们用的 Pixel 9），每通电话自动检测；其他手机上 AI 会先说完那一句。 |
| 静默处理 | ✅ 先问对方还在不在，再结束通话。 |
| 语音检测、噪声 | ✅ 用 Gemini 的，或本地检测器。 |
| 自然的环境感 | ✅ 12 种背景音、三档音量。 |
| 骚扰与机器人电话 | ✅ 拦截号码；三道防线（回复白名单、加权关键词、语义复审），再选礼貌拒绝或陪聊模式。 |
| 认出常打来的人 | 🟡 通讯录让 AI 知道来电者的名字和你的备注。同一号码之前的摘要还不会放进提示词。 |
| 按知识库回答、不乱编 | 🟡 “AI 可以回答的资料”：放在提示词里的纯文本，加上“不要猜”的规则。没有文档检索。 |
| 披露 AI 身份、录音告知 | 🟡 “AI 助理”身份内置披露，“本人”身份被认真问到时一定承认。录音告知要写在你的提示词里。 |
| 防提示词注入 | 🟡 每份提示词都有固定规则；没有单独的过滤器。 |

### 语言

| 需求 | 现状 |
|---|---|
| 多语言、本地化提示词 | ✅ 九种完整语言（语音、提示词、控制台、应用、通知）。繁体中文经过真实通话验证，其他语言经过模拟通话验证。 |
| 识别语言、通话中切换 | ✅ 开场由来电号码和 SIM 卡决定；通话中 AI 跟着对方换语言。用 28 种语言的来电者模拟过。 |
| 双卡、每张卡各自的语言 | ✅ “各 SIM 卡的主要语言”。 |
| 文字记录翻译 | ✅ 其他语言的句子保留原文，附上翻译成你通知语言的对照。 |
| 方言与口音 | 🟡 模型听得懂多少就是多少；我们没有额外调整。 |
| 来电者与真人之间的实时翻译 | ❌ |

### 替你办事

| 需求 | 现状 |
|---|---|
| 替你拨出电话 | ✅ AI 代打：实时字幕、向你提问（`ask_owner`）、通话中交代、结构化结果、接续再打。模拟验证过，等待真手机的反馈。 |
| 预约时间 | ✅ AI 记下请求但不当场答应；你在“待处理事项”或 Telegram 卡片上同意或不同意；对方通过短信或 AI 回拨收到答复。 |
| 日历 | ✅ 一键添加到 Google、Outlook.com、Microsoft 365、Apple、Yahoo 或 `.ics`，不用连接任何日历账号。 |
| 短信回复 | ✅ 预约答复从接这通电话的 SIM 卡用短信发出。收到的短信可以用短信转发器转出去。 |
| 通讯录 | ✅ 从 vCard、CSV、TSV、纯文本、Excel、Word 导入，PDF 和图片交给 Gemini；合并重复；导出 vCard。 |
| 通话中使用工具 | 🟡 `propose_appointment` 与 `ask_owner`，各自受严格的状态机管控。有意不开放任意工具。 |
| 通话摘要、意图、待办 | ✅ 四行摘要，预约变成待处理事项。没有情绪分析或统计仪表盘。 |

### 运行

| 需求 | 现状 |
|---|---|
| 自带密钥、没有平台按分钟计费 | ✅ 一个 Gemini 密钥覆盖全部；摘要可以改用任何 OpenAI 兼容服务或本地模型。 |
| 所有数据存在自己的电脑上 | ✅ 发给模型和通知服务的内容除外。 |
| 通知、webhook、n8n／Zapier | ✅ 16 种渠道，包括电子邮件和 JSON webhook；其他用 REST API。 |
| 网页控制台、任何设备都能打开 | ✅ `bageo.local`、二维码、添加到主屏幕。 |
| 一步启动 | ✅ Windows、macOS、Linux 启动脚本；Docker 镜像。 |
| 备用机切回普通手机 | ✅ 控制台或应用一键切换；应用不需要 root。 |
| REST API | ✅ MCP ❌ |
| 营业时间、节假日 | ❌（简单的情况可以用状态留言） |
| VIP 号码直接转人工 | ❌ |
| 附摘要转接人工 | ❌ 手机应用还不能桥接通话。 |
| 紧急关键词处理 | ❌（AI 代打绝不拨打紧急电话） |
| 花费上限、每日通话上限 | ❌ 只有最长通话时间的设置；请在 API 提供商那边设置预算。 |
| 完全本地的语音流程（Whisper／Ollama／Piper） | ❌ 支持的模式里没有。代码里有一套旧流程，未维护。摘要已经可以用本地模型。 |
| SIP／Asterisk／FreeSWITCH | ❌ 不是目标；不过手机通信协议很小、有文档，SIP 前端可以取代手机。 |
| 多租户、白标 | ❌ 没有计划。 |
| CRM 集成 | ❌ 请用 webhook。 |

## 接下来值得做的

大致按“投入换来的效益”排序：

1. **真实使用的反馈**：AI 代打在真手机上拨出、其他手机型号、其他语言、Telegram 以外的通知渠道。这比任何新功能都重要。
2. **来电记忆**：除了联系人名字和备注，把同一号码最近几次的摘要放进提示词。
3. **按号码的规则**：一定大声通知的 VIP、绝不陪聊的号码、特定联系人用不同的提示词。
4. **营业时间**：时间外改用不同提示词或播放一段语音。
5. **手机报告更清楚的通话状态**：拨出的电话被接起的那一刻就报告，让待处理事项和代打页面不用靠听人声，就能分辨“已接通”和“还在响”。
6. **从手机应用转接／三方通话**，让真人可以接手。
7. **同一套通话逻辑换用其他实时模型**（OpenAI Realtime，以及逐渐成熟的本地语音对语音模型）。
8. **移除旧的菜单式代码路径**，让主程序更易读。
9. **macOS 与 Windows 的签名、公证发布版**。
